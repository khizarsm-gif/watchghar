# Watch Ghar

Online watch store: catalog, cart, checkout that saves orders, and an admin portal
(products, categories, orders, team). Dark and gold design.

Stack: Next.js 14 (App Router), React 18, TypeScript, Tailwind CSS, Supabase
(Postgres, Auth, Storage), hosted on Vercel.

## 1. One-time setup

1. **Supabase**: create a NEW project (do not reuse another store's project).
2. In the Supabase **SQL Editor**, run these files in order:
   1. `supabase/migrations/20261005000000_base_schema.sql`
   2. `supabase/migrations/20261006120000_orders.sql`
   3. `supabase/seed_demo.sql` (optional demo catalog; every row is flagged as demo)
3. **First owner login**: Authentication -> Users -> Add user (email and password).
   Then run in the SQL Editor (replace the email):

   ```sql
   insert into public.admin_users (user_id, role, email, display_name)
   select id, 'owner', email, 'Owner' from auth.users where email = 'you@example.com';
   ```

4. **Environment variables**: copy `.env.example` to `.env.local` and fill it in
   (Project Settings -> API for the URL and keys). Add the same four variables in
   Vercel. `SUPABASE_SERVICE_ROLE_KEY` is a secret: server only, never commit it.
5. **Business details**: edit `config/business.ts`. Every phone number, address and
   hour in it is a PLACEHOLDER. Orders and WhatsApp links use these values, so set
   real ones before launch.

## 2. Run locally

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production check
```

Admin portal: `/admin` (sign in with the owner account from step 1.3).

## 3. Deploy

Push to GitHub, import the repo in Vercel, add the environment variables, deploy.
Vercel Hobby is for non-commercial use only; a store should run on a paid plan.
Supabase Free projects pause after a week of inactivity and have no daily backups;
plan for Pro before taking real orders.

## 4. Day-to-day

- **Products and photos**: `/admin/products` (upload photos, set sale price, stock,
  featured). Put watch specs in the "key information" box, one per line.
- **Categories**: `/admin/categories` (owner only).
- **Orders**: `/admin/orders`. Statuses: new, confirmed, out for delivery (delivery
  only), ready for pickup (pickup only), completed, cancelled. Every change is logged.
- **Team**: `/admin/team` (owner only): owners do everything, purchasers manage
  products and orders.

## 5. How orders work

- Checkout calls a server action that runs the `create_order()` database function with
  the service role key. Prices are read from the `products` table, never trusted from the
  browser. Limit: 5 orders per phone number per hour.
- Stock is checked at order time but not reduced automatically. Adjust stock in the
  admin portal when you confirm an order.
- Payment: cash on delivery or pay at store. There is no online payment yet.
- After placing an order the customer sees a confirmation and can send it to your
  WhatsApp with one tap.

## 6. New-order email alerts

When a customer places an order, the store gets an email with the order details
(sent from `lib/order-email.ts` through Brevo's transactional email API). Set these in
Vercel -> Settings -> Environment Variables, then redeploy:

| Variable | Purpose |
| --- | --- |
| `BREVO_API_KEY` | API key from the Brevo account. Secret: never commit it. |
| `ORDER_NOTIFY_EMAIL` | Where alerts go (comma-separated for several addresses). |
| `ORDER_FROM_EMAIL` | Sender address. It must be added and verified as a sender in Brevo. |

If any variable is missing or the email service is down, the order is still saved
and shown in `/admin/orders`; the email is only an alert.

## 7. Before you launch (checklist)

- [ ] Real contact details in `config/business.ts` (phone, WhatsApp, address, hours)
- [ ] Real products and photos; delete demo products
- [ ] Replace the placeholder Terms and Privacy pages with reviewed text
      (have a qualified person review them)
- [ ] Set `NEXT_PUBLIC_SITE_URL` to your domain
- [ ] Logo: `public/images/logo.svg` is a simple placeholder wordmark
- [ ] Hosting plan and database backups decided (see section 3)
- [ ] Brevo email variables set in Vercel and a test order email received
- [ ] Place a test order end to end and confirm it appears in `/admin/orders`

## Project structure

```
app/            pages, admin portal, server actions
components/     shared UI
config/         business.ts (the one place for store details)
data/           catalog data access (Supabase)
lib/            helpers (orders, whatsapp, supabase clients)
public/images/  logo, hero and demo product art (generated by scripts/generate-placeholders.py)
supabase/       migrations/ (run in order) and seed_demo.sql
```
